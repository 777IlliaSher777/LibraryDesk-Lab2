# CODING STANDARD

## 1. Загальні положення

Цей документ визначає правила написання, оформлення та підтримки програмного коду проєкту LibraryDesk.

LibraryDesk — консольний застосунок для ведення каталогу бібліотеки та обліку видачі книжок читачам.

Основна мета стандарту — забезпечити зрозумілість, однаковість і підтримуваність програмного коду.

Стандарт поширюється на всі проєкти рішення LibraryDesk, написані мовою C#.

## 2. Правила іменування

Для іменування програмних елементів використовуються загальноприйняті правила C#.

| Елемент | Правило | Приклад |
|---|---|---|
| Класи | PascalCase | Book, Reader |
| Методи | PascalCase | AddItem |
| Властивості | PascalCase | InventoryNumber |
| Локальні змінні | camelCase | readerName |
| Параметри | camelCase | inventoryNumber |
| Приватні поля | _camelCase | _bookList |
| Перелічення | PascalCase | LoanStatus |
| Значення enum | PascalCase | Returned |

Назви повинні бути зрозумілими та відображати призначення елемента.

## 3. Правила форматування

- Використовується кодування UTF-8.
- Для відступів використовуються 4 пробіли.
- Максимальна довжина рядка — 100 символів.
- Відкривні фігурні дужки розміщуються на новому рядку.
- Кожен файл повинен завершуватися символом нового рядка.
- Між логічними блоками коду залишаються порожні рядки.
- Форматування перевіряється командою `dotnet format`.

## 4. Коментарі та документація

Коментарі використовуються для пояснення складної або важливої логіки програми.

Коментарі повинні бути короткими, зрозумілими та актуальними.

Назви класів, методів і властивостей повинні бути достатньо інформативними, щоб не потребувати зайвих коментарів.

XML-документація використовується для опису публічних елементів відповідно до вимог наступних лабораторних робіт.

## 5. Структура проєкту

Рішення LibraryDesk складається з двох проєктів:

- `LibraryDesk.Core` — містить основну логіку програми та доменні сутності.
- `LibraryDesk.App` — містить консольний застосунок і точку входу `Program.cs`.

Основні сутності проєкту:

- `Book` — книжка бібліотеки.
- `Reader` — читач бібліотеки.
- `Loan` — документ видачі книжок.
- `LoanItem` — окрема позиція документа видачі.
- `LoanStatus` — перелік можливих станів документа.

Логіка роботи з доменними сутностями повинна зберігатися в проєкті Core, а взаємодія з користувачем — у проєкті App.

## 6. Правила Git-комітів

Для повідомлень Git-комітів використовується англійська мова.

Повідомлення повинні коротко описувати виконану зміну.

Використовується формат Conventional Commits:

- `feat:` — додавання нової функціональності.
- `fix:` — виправлення помилок.
- `docs:` — зміни документації.
- `chore:` — технічні зміни та налаштування.
- `refactor:` — зміна структури коду без зміни поведінки.

Приклади:

```text
feat: add library book entity
fix: correct loan status handling
docs: add coding standard
chore: configure code analyzers
```

## 7. Машинно закріплені правила

Дотримання стандарту перевіряється автоматичними інструментами:

| Правило | Інструмент перевірки |
|---|---|
| Форматування коду | `dotnet format` |
| Стиль C# | Roslyn Analyzers |
| Правила оформлення | StyleCop.Analyzers |
| Іменування приватних полів | `.editorconfig` |
| Налаштування аналізаторів | `Directory.Build.props` |
| Успішність компіляції | `dotnet build` |

Автоматичні перевірки допомагають виявляти помилки форматування, порушення правил іменування та інші проблеми коду.

Усі зміни повинні відповідати цьому стандарту.
